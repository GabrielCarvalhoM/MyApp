## Executable scope

This is a finite coaching domain interpreter over approved synthetic contexts, not a general planner, population dosing model or complete autonomous V1 coach. It evaluates real guard logic and returns supported decisions/proposals; it never applies them. It contains no LLM, UI, ViewModel, network service or dynamic policy generator. Node24 runs the module without an app. AJV is the one locked runtime dependency, used solely for input-contract validation; no sport semantics come from that dependency. This language choice does not select a future iOS/backend architecture.

The bundle compiler verifies all57 ACF review-target hashes and registry/independent-record equality. ACF policy declarations marked pending are not silently treated as approvals: independent records govern only their exact item/action conditions. The20 projected policy families include control-only limited items; limited recommendations never enable a positive dose. Approved context programs additionally bind concrete recipe reviews and exact E2E witness reviews. S13/S14/S29 successors bind their independent SDC records and recipe catalog. Original historical QUESTIONABLE cases are untouched.

Supported positive outputs: exact next-horizon easy30→35, squat60→62.5, squat60→57.5, named familiar novice initial selection per subject, observed-response ranking of a pre-reviewed next-horizon schedule, and selected SDC prospective move/reduction/remainder witnesses. Repeated evidence counts and numeric doses are exact fixture premises, never universal gates. The same easy35 dose appears in E2E04/05; six positive ACF decisions do not mean six independent dosing rules. Current adequate work stays stable. No automatic compensation, concurrent escalation or repeated decrement sequence is implemented.

Exact accepted cruise-end and optional-calf-withdrawal branches are KEEP/execution interpretations, not new prescriptions: original/chosen/actual targets remain distinct. A broad accepted range does not authorize a newly calculated microchange. Configured substitutions without complete concrete joint approval ASK/HOLD; no equivalent-load conversion. Wearables never create a fatigue/readiness score or independently prescribe/veto. Novel sensor contexts are outside this finite executable subset. Return, combined taper and unsupported calibration/fatigue trajectories fail closed.

## Input and state

`SHADOW_INPUT_SCHEMA.json` executes before policy selection, after immediate explicit purpose/clinical boundary routing. Inputs include athleteState, immutable officialPlanState, event, observation, observedExecutionState, recoveryContext, policyContext, and optional exact athleteResponseHistory / preacceptedBranch / planContext. InputVersion, explicit synthetic purpose, event ID, source revision, coverage, association and injected evaluation timestamp are required. Unknown metadata is not normal/zero. Malformed input yields a typed nonprescribing decision; raw supplied metadata remains in the trace.

AthleteState and TrainingPlan/PlannedSession preserve the supplied ACF structures. Completed daily activities require explicit subject/session/executed revision, canonical whole-session fact ID, actual prescription, coverage and observation time. Missing uploads never prove an omitted session. Daily work is independently checked against its immutable target; duplicate canonical facts cannot become two completed sessions. Additional observation/inference/context is never discarded. G03 helpers separately handle known segments, explicit corrections, suppression, exact dimensional comparison and unknown remainders without physiological conclusions.

Recovery is qualitative. Explicit clinical dependencies route CLINICAL_HUMAN_REQUIRED before unknown eligibility. Unknown eligibility asks; nonclinical interruption does not restore former capacity. Clinical holds are never released by a biomarker, confidence, acceptance or elapsed time. `routeBoundary` emits no dose.

The four output states are `officialPlanState`, `observedExecutionState`, `shadowDecision`, `appliedState`. For every evaluation, including B proposals and A ceilings:

`appliedState == officialPlanState`

All snapshots use JSON value semantics and are deeply frozen; the caller's inputs are never mutated. There is no apply/start/export API. Returned autonomy is only the contractual ceiling, never operational permission. MODIFY maps to existing AEC action classes (REPLAN, MOVE, REDUCE_VOLUME); RECONCILE uses ASK. MEC retains the existing explanatory0..6 degrees; a retained/HOLD decision has zero change, even when an unsupported source candidate would have larger scope.

## Guard and policy execution

Purpose → explicit clinical dependency → input schema → eligibility/continuity → identity/provenance/source reconciliation → current registry/context/holds → exact athlete/plan/facts/branch/history applicability → every dependent current review → deterministic rule program → trace. No high confidence bypass. Revocations or new context suspend use immediately; no invented TTL or hysteresis threshold.

`POLICY_REGISTRY_RUNTIME_BINDINGS.json` contains id/version/hash, required inputs, eligibility, evidence disposition, exact conditions, actions, preserve, trade-offs, MEC relevance, forbidden shortcuts, fallback and review triggers. Bundle/profile fingerprints are applicability bounds rather than security signatures or scientific proof. Raw facts and normalized prescriptions are bundled; expected action/autonomy/MEC oracles are isolated in `e2e-oracles.json` and are never imported by the evaluator. Candidate resources use independently reviewed explicit prescription fields and named deltas. Recompilation is authoring/verification, not runtime policy generation.

E2E16 explicitly ranks a prospective WED lower alternative against the selected MON lower / THU cruise option. Its frozen official base already has MON placement; the output is a next-horizon alternative comparison, never a patch claiming the official lower was on WED. The source-described WED comparison is not a validated complete-week prescription. Learning is observational, scoped, purpose-bound and cannot infer12/36h thresholds. S29-R2 explicitly selects the remaining RDL/split work and omits only unperformed sq-3; original sessions and executed prefix are retained separately.

## Decision and audit contract

`SHADOW_DECISION_SCHEMA.json` defines id/traceId, decision/action type, autonomy, preserve/modify, MEC, rationale/JEV SHADOW, evidence/policy refs, confidence, missingInputs, mustNot, nextCheck/owner/exit, unsupportedDependency, input/policy hashes, candidate comparisons and timestamp. Positive proposals resolve full target session maps or explicit selected remainder, with subject/base/hash and future confirmation requirement. No applied efficacy or guaranteed RIR/response is asserted.

The evaluation clock is injected. Identical complete input yields an identical decision/trace. `ShadowJournal.record` deduplicates replay of the same complete logical evaluation in memory; persistence, cross-process delivery ordering and production application do not exist. No duplicate application is possible because application is absent. Delivery correction/suppression control must be supplied explicitly to the semantic helper at each replay frontier.

The simulation journal records164 evaluation rows and160 unique inputs, with an evaluation index preserving corpus/label→traceId for duplicate uses. Frequencies are designed-case conformance; never efficacy/safety, general-population coverage or real-world stability. Scripted compatible daily responses are facts supplied by the harness, not simulated physiology. The four-week observation stream never adopts the proposed doses or pretends to measure response to them. Unresolved fatigue/race holds persist in stress trajectories.
