## What I checked and found sound

- **No shell anywhere.** Every spawn is argv-only (`proc.mjs:100,137`). `parseCmdShim` resolves only npm-style shims found in PATH directories. Node/libuv on Windows does not resolve `git` from the child's cwd: probe with a planted `git.exe` (copied `hostname.exe`) still ran the real git.
- **No destructive Git in the runtime.** The only mutating calls are `worktree add` (`git.mjs:104-108`), `add -A` and `commit` in the Codex job worktree (`git.mjs:132-136`), plus read-only status/diff/ls-remote/fetch. Nothing in the runtime pushes, resets, deletes a branch, removes a worktree or rewrites history (grep over `lib/`). No core.hooksPath is set and no active hooks exist in `.git/hooks`.
- **Permission modes at creation.** `bypassPermissions` and `dontAsk` are rejected at mission creation (`mission.mjs:18,121`), with a guard test. Every session gets `--permission-prompts none` and an explicit model and effort. The gap is reload (SEC-1), not creation.
- **Codex invocation.** Codex always runs with `-s workspace-write`; no bypass flag ever reaches it (`executors.mjs:234`). The brief goes in on stdin.
- **Codex job checks.** Outside-path changes leave the work uncommitted. The commit parent must equal the mission HEAD. Acceptance results are verified independently of Codex's own report, which is labelled "claims, not verified" in the handoff.
- **Path inputs.** `repoPath` rejects `..`, `.`, backslash, a leading `/` and drive letters (`checkpoint.mjs:82-93`). `runtime:` refs are only checked for existence and hashed, never written. `safeId` sanitises unit ids for job directories and branches. The mission id is pattern-checked. `--worktree`, `--branch` and `--base` are Founder CLI input. All writes go to the mission worktree, the job worktree or `.agent-runtime/` (apart from SEC-1's slug/main_root case).
- **Gate integrity (§12, §25 B/D).**
  - A checkpoint must have the exact next seq and the current `run_seq`, so stale files cannot be replayed. A leftover `checkpoint.next.json` is moved aside before a fresh session (`supervisor.mjs:259-262`).
  - Dropping `do_not_reopen`, invariants, freeze or findings, or silently downgrading a blocker, is rejected (`coherence.mjs:149-173`).
  - `CLOSED_READY`/`COMPLETE` with an open blocker is rejected (`checkpoint.mjs:236`).
  - A final state requires `next_unit: null` and a verified push. `COMPLETED`/`BLOCKED`/`FOUNDER_REQUIRED` stop the loop. `--resolve` refuses a terminal mission. The validator rejects any checkpoint after `COMPLETED`.
  - Edits to the accepted checkpoint are detected by sha256 (`supervisor.mjs:96-103`), with re-anchoring only by the Founder. The correction loop is bounded and runs in the same session.
  - The limits on this: SEC-1 (state/mission reload) and SEC-5.
- **Recovery (§14).**
  - A live pid blocks recovery unless `--assume-dead` is passed. With pid reuse, that fails safe.
  - Interrupted jobs are handed on as `INTERRUPTED`.
  - Unexpected dirty paths block, are recorded, and are never deleted. Rejected or leftover checkpoints are renamed, never removed.
  - State writes are write-then-rename. A truncated last JSONL line is tolerated.
  - The gaps: SEC-7 and SEC-8.
- **Secrets.** No credential is logged by the runtime itself. Auth probes keep only status fields. Everything in `.agent-runtime/` stays ignored by Git (`.gitignore`), and creation refuses a base where it would not be.
