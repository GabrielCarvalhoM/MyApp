## Binding rules (quoted or closely paraphrased)

- **Total UI/UX decontamination:** the previous Figma and old UI/UX documents, references, decisions and explorations are not visual or experience authority. No pixel migration, no harmonization with the old file, no use of the old file to fill gaps.
- **Repo = functional truth; new Figma = experience truth.** Documentation may be used for capabilities, domain, entities, data, Adaptive Engine, Run/Strength Intelligence, Athlete Model, ACF, training policies, onboarding needs, units, languages, structure of workouts, shareables, history, integrations, adaptation behavior, scientific limits, confidence states, V1 scope. It may not be used for appearance, composition, visual system, old navigation, old card model, old home or aesthetic references.
- **Truth limits of the UI:** no readiness score without contract, no arbitrary fatigue/recovery score, no false confidence, no magic percentages, no "AI detected X" without evidence, no psychological inference, diagnosis or invented injury risk. Low-information states must stay elegant. Internal codes (ASK/HOLD/ABSTAIN/NOT_SUPPORTED_YET) get end-user representations that preserve the underlying truth.
- **Adaptive Engine experience:** stable by default; plan → execute → record → learn → check validity → preserve if valid → smallest sufficient change if not. Material adaptations explain what happened, why it matters, what is preserved, what changes and why it is the minimum.
- **Run-first / Strength-first / Balanced** are priority policies, not themes; Balanced is not Run-first in disguise; no invented differences without real conflict.
- **Flows to complete:** onboarding (no language question; language lives in Settings), first plan/first value, Today (all listed contexts), Plan, mandatory pre-workout detail, run execution, strength execution, informative workout completion, adaptations (all listed cases), recovery/readiness (recovery state ≠ session readiness ≠ plan decision; rich/partial/no-wearable/conflicting/subjective/insufficient baseline), history, progress (no vanity metrics), shareability (full cards, run with route, transparent overlays), settings/profile (units, PT/EN/ES language, integrations, notifications, data/permissions), event/race.
- **States and stress tests** for critical flows; componentization where it pays off; short, mature, specific copy; preserve the new Figma's visual direction.
- **Final adversarial audit** (completeness, continuity, truthfulness, depth, simplicity, low-data, stress, consistency, professional quality) and correction of problems found.
- Do not: use the old Figma, reintroduce old UI or rules, create a parallel visual concept, redo current screens by preference, turn the product into a dashboard, add out-of-V1 features, Social/Crew, nutrition plans, invented physiological data, fake universal auto-adaptation, AI buzzwords, or flows represented by a single conceptual screen.
