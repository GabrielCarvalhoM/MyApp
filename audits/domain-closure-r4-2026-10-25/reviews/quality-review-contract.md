# R4 independent quality contract

Reviewer `/root/holdout_quality` owns independent holdout authoring and the executable coaching-quality/adversarial review. Runtime implementation, scientific envelope approval, Product Truth, UI, production, KMP and real-user state are outside this ownership. Other authors are working concurrently; their artifacts are not modified by this judge.

Effective capabilities: Node v24.19.0, unrestricted project filesystem and shell tools. Browser/device coverage is not applicable to this offline Node reference mission. No human sports credential or clinical authority is claimed. The review uses QUALITY 1.1.0, verify-domain-gate 1.3.0 and verify-before-completion 1.3.0. The root task owns aggregate routing; this independent review is an L2 judge boundary within that task.

Inputs: the frozen R3 normal40, the separately sealed R4-HO-1.0.1 cases and the exact submitted runtime/envelope/scientific-review revisions. The holdout seal exists before this reviewer reads the R4 implementation. Node execution must occur before a readiness claim. Source inspection alone cannot substitute for execution.

Acceptance: the runtime uses facts rather than corpus oracles; scientific boundaries are enforced; selected actions are concrete and executable when information is sufficient; goal/phase/priority/history shape ranking; material trade-offs and rejected alternatives are traceable; change is no larger than necessary; missing material facts yield useful ASK; clinical/unsupported scope stays outside coaching; original/applied state remains unchanged; historical regressions remain current.

Quality classes: COACHING_BEST_SUPPORTED, COACHING_ACCEPTABLE_ALTERNATIVE, COACHING_SUBOPTIMAL, INSUFFICIENT_INFORMATION, UNSUPPORTED and CLINICAL_OUT_OF_SCOPE. The runtime's own quality label is not accepted as the independent judgment. A materially dominated but admissible option is not strong coaching. No arbitrary percentage gate is introduced.

Adversarial probes will target scientific approval/envelope tampering, contraindications, synthetic-only restriction, facts/schema integrity, completed-prefix preservation, case-ID/oracle independence, priority/goal/phase contrasts, history duplicates/noncomparability/single-event learning, missing capacity, contradictory recovery signals, schedule infeasibility and shadow immutability. Probes will be selected after the implementation interface is submitted, without altering the sealed holdout.

STOP_WHEN: criteria have current executable evidence and reviewed hashes, or a concrete essential evidence/behavior blocker is reproduced. Findings return REQUEST_CHANGES to the runtime owner; this judge will not silently repair judged code. New relevant code/envelope changes invalidate affected results and require targeted re-evaluation.
