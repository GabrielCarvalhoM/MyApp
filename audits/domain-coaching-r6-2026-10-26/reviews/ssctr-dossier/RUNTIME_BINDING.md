# R6 runtime binding for the SSCTR review

Prepared by the runtime author (continuation root) for the independent SSCTR reviewer. It describes what the code does with each boundary in `CoachingCore/r6/PROGRAM_POLICY_R6.json`. It is not evidence of scientific adequacy. The reviewer should check the code, not this summary.

Activation: `src/r6-authority.mjs` enables a boundary only when an independent record in `audits/domain-coaching-r6-2026-10-26/reviews/ssctr-policy-review.json` matches `boundaryId`, the exact `policyHash` (`src/value.mjs` canonical SHA-256 of the policy object), `independent:true`, a non-empty `sourceIds`, and an enabling disposition. APPROVE or APPROVE_WITH_CONDITIONS needs WELL_SUPPORTED or SUPPORTED_WITH_LIMITS. LIMITED_REVERSIBLE_RECOMMENDATION needs SUPPORTED_WITH_LIMITS or PLAUSIBLE_BUT_UNCERTAIN. Any other outcome leaves the boundary disabled, and the runtime fails closed as listed below. Development outputs in `DEV_OUTPUTS.json` use a test authority that enables every boundary, so the reviewer can see the behavior that approval would allow.

| Boundary | Where it acts | What it permits | Fail-closed behavior without approval |
|---|---|---|---|
| R6-COLD-START | `r6-intake.mjs` canonicalization; `r6-program.mjs` `generateProgram` | A complete conditional program from onboarding-like facts. Unknowns are classified as conservative establishment, ASK, learn in first sessions, or clinical/out of scope. Week 1 never exceeds reported running. | No program; status UNSUPPORTED. |
| R6-LOAD-ESTABLISHMENT | `r6-program.mjs` `strengthDose` / `strengthRowsFor`; `r6-prescription.mjs` `exerciseRow` | Novices do unloaded practice first (1×5, RIR≥3), then effort-guided load selection (2×8, RIR≥3). Familiar-unknown-load athletes establish at goal reps (≤2 sets, RIR≥3). Load is never derived from sex, body size or another exercise; a stale known load is only a "hint". | A strength program without known loads is not generated. |
| R6-PLANNED-PROGRESSION | `initialRunState`/`advanceRun`, `initialStrengthState`/`advanceStrength`, `runRow`, `strengthDose` | Planned steps are response-gated. Long run +5 min per development week up to an event or goal target capped by the athlete's time. Every second development week one easy run (rotating) gains +5 min, so weekly running rises by about one step at a time. Consolidation every 4th development week (long run −10 min, strength sets −1). Strength: double progression +2 reps/week within the goal range, then the smallest increment; strength goal +increment every second week; +1 set after the first development block. Walk/jog follows the policy ladder one step per week. | No program. |
| R6-RUN-QUALITY | `arrangementCandidates`, `distributeRun`, `qualityPrescription` | At most one quality session per week. Only for EASY_CURRENT/QUALITY_FAMILIAR runners with a RACE or PERFORMANCE goal and ≥3 run days, after 2 observed weeks (immediately for a familiar quality task). Threshold ladder first; event-specific ladder only after 2 threshold sessions. Strides after 2 established weeks. Never adjacent to the long run when another day can hold it. Effort cues only; `paceFromGoalTime:false`. | Easy running only; no strides. |
| R6-HYBRID-ARRANGEMENT | `r6-balanced.mjs` `interferenceCosts`, `horizonCosts`, `chooseBalanced`; thresholds in `operational.hybrid` | Ordinal costs by direction and gap. Pareto first, then lowest worst-case joint harm under the phase lead. A tie with opposing costs is asked, never resolved by candidate order. Unknown arrangement-level recovery stays admissible when whole-week tolerance covers the same tasks. | Costs are not computed. Any real trade-off between Pareto candidates becomes ASK. |
| R6-SUBSTITUTION | `r6-adaptation.mjs` `equipmentChange`; `r6-catalogue.mjs` `substitutesFor`; legacy `legacyCandidates` | Same-pattern substitutes with available equipment, familiar first. Unfamiliar substitutes are effort-established and capped at 2 sets. No load conversion. Bodyweight-for-load swaps are disclosed as a different stimulus. A pattern without a substitute is left out and disclosed. | Equipment change → UNSUPPORTED. |
| R6-NONCLINICAL-RETURN | `returnAfterPause`; RETURN modes in `runRow`/`advanceRun`/`strengthDose`; legacy RETURN branch | Short (≤10 days): resume the last completed doses; the next step waits; the first quality slot is easy. Moderate (11–28 days): run entry from a current demonstration (≤7 days, compatible) or the R4 entry (15 min), then a midpoint, then the prior dose (2 conditional steps); strength 1 set at RIR≥4 with the prior load only as a ceiling, then prior sets −1, then prior. Long (>28 days): restart class. Clinical or possibly clinical reasons route to a human; an unknown reason is ASK. | RETURN → UNSUPPORTED. |
| R6-EVENT-TRANSITION | `planPhases`, `eventWeekSessions`, `buildWeek` race week; legacy `eventTransform` | Taper week: long run ≈0.62×achieved peak; easy ≈0.7× (10K 0.8×); quality same effort at ≈55% reps; strength sets halved at RIR≥3. Race week: easy runs ≈0.5×; a race-effort touch ≥3 days out (10K 3×2 min, HM 2×5 min) for quality runners; optional shakeout the day before; strength one session at 1 set RIR≥4 ≥3 days out. Race day. Post-event: rest for 2 days, then optional easy 20–30 min and one light strength session. No new exercises; rotation deferred. | An event program is not generated (cold start). The legacy path keeps the taper and race weeks UNSUPPORTED unless the athlete supplied a familiar event week. |
| R6-PARTIAL-NOISY-LEARNING | `r6-provenance.mjs`, `r6-learning.mjs`, `weeklyGates`; legacy `phaseClassModel` | Causal time (no future or future-reported facts; day-precision gets the latest causal instant). Duplicates merge across sources. Same-id-different-facts and disagreeing duplicates are quarantined. Stale facts (>56 days) expire. Partial executions count only for adherence and hold the step. Missing effort/HR is unknown. Repeated adverse responses (≥2 in 14 days) regress; after a regression only responses at the new dose count toward another one (hysteresis). The completed-work ledger never expires; staleness only removes facts from learning and gating windows. Repeated surplus (≥3 over ≥7 days) earns one extra step outside event phases. | The athlete model is not updated; gating still uses the completed-work ledger. |
| R6-ROTATION | `skeletonOf().rotation` | Accessories only, on the preference cadence (coach decides = 6 weeks), deferred in specific/taper/race/post-event and establishment weeks. A new exercise starts with effort-guided establishment. FIXED never rotates. | No rotation; the preference is recorded. |

Population and scope guards (not boundaries; always on): 18–80 software range; pregnancy, postpartum, adolescent and elite are out of V1; marathon and ultra events are out of scope. Clinical flags always give CLINICAL_HUMAN_REQUIRED, with no substitute dose.

## Change log during review

- 2026-10-26: easy-run progression changed from all easy runs at once to one rotating easy run per step; regression hysteresis added; completed-work ledger no longer drops facts older than 56 days; continuous running after the walk/jog ladder starts at 25 minutes. Policy file and hash unchanged.
- 2026-10-26 (later): rotation deferred during return; taper reduces two-repetition quality sessions by shortening repetitions (`reducedWork`); a self-reported familiar quality task keeps its own work and takes its family's effort cue when the athlete gave no effort text (CRUISE is read as THRESHOLD); goal/event-date reviews with nothing new ask for the missing fact or keep; a performance report naming no session keeps the plan. Policy file and hash unchanged.
- 2026-10-26 (later): interference cause labels now distinguish "shortly before a key run (same session)" from "the day before" (same severities and thresholds); a selected KEEP is always admissible (logged loads equal to the plan no longer mark it inadmissible); a rebuild (learned rearrangement, schedule or goal change) records the gates it applied, so regression hysteresis counts a regression applied there and the next adverse response holds instead of regressing again. Policy file and hash unchanged.
