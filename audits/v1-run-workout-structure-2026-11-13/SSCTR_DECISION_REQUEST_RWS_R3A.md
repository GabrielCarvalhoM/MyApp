# SSCTR amendment request r3a — measured vs confirmed distance, and CT-3 history (2026-11-13)

Requester: Chief. Final product consistency check (Founder, 2026-11-13). Architecture and the central r3 rule are approved and not reopened. Only two approved r3 rules change; everything else in `SSCTR_RWS_R3_DECISION.json` stands.

**Founder rule:** a distance session reaches its target only when the distance was actually covered. 15.52 km measured does not by itself show that 16 km were run. Do not invent executed distance to offset GPS error; allow explicit correction/confirmation when there is reasonable evidence of measurement failure, preserving the originally recorded value; never demand absolute sensor precision; never turn a technical tolerance into a fictitious sporting completion.

| Q | Change | Author proposal |
|---|---|---|
| A1 (amends r3 C3) | Remove "GPS ≥ 0.97 × target counts automatically". Separate four facts: **measured** distance (immutable, with source and quality), **declared** distance (athlete correction, with reason), **source reliability**, **target met** (with basis). | Target met only by: **MEASURED** measured ≥ target (track/course count, treadmill display, GPS, device lap); **CONFIRMED_CORRECTION** measured < target, athlete declares ≥ target with a measurement-failure reason (signal loss, auto-pause, device restart, tunnel/buildings), recorded as GPS quality POOR, and measured ≥ 0.91 × target (r3's largest documented under-reading) — lowest tier, never pace evidence; **DECLARED** no device, explicit declaration ≥ target — lowest tier, never pace evidence. Otherwise: below target without confirmation → PARTIAL + ASK offering correction; confirmation without a failure reason, or below 0.91 with good GPS → UNKNOWN (conflict, ASK). Repetitions: the lap decides (unchanged). |
| A2 (amends r3 C1 CT-3, C2) | CT-3 `D ≤ 1.10 × longest run of the last 30 days` must be proportional to history and data availability. | (i) Classify CT-3: conservative heuristic anchored on Frandsen 2025's ≤10% reference group, not a safe threshold. (ii) The longest run may come from any recorded source — engine ledger, HealthKit import, intake-declared recent longest run with its date, manual entry — at face value for CT-3 (it bounds distance expression, not the dose), but a DECLARED/CONFIRMED_CORRECTION distance counts only up to its measured value. (iii) Confirm that failing CT-3 only changes the expression to TIME (the planning dose and the engine's progression are unchanged), so it never blocks training. (iv) Rule whether EXPERIENCED athletes may use a longer window when the 30-day window is empty for a recorded reason (taper, travel), or abstain. |

Requested output: `ssctr/SSCTR_RWS_R3A_AMENDMENT.md` + `.json` with amended `values` (`RWS-R3A-1`) and worked examples: 16 km with GPS 15.52 unconfirmed; same confirmed with a signal-loss reason; same confirmed without reason; GPS 14.0 confirmed, good GPS; no device declared 16 km; track 16 km; EXPERIENCED athlete whose only recent long run (15 km) is an intake declaration; an athlete with an empty 30-day window after a recorded taper.
