## HP-01 — Problem, owners and competing structures

The present control framework can assess whether an existing plan remains valid. It cannot create an initial plan simply by invoking an adaptation rule against imaginary history. This foundation supplies a constrained initial-planning contract: choose supported sessions, validate both modalities together, place them in actual windows and expose unresolved trade-offs before adoption. Run and Strength own session semantics; Recovery/Load owns shared exposure projections; the AE owns the single integrated plan. There is no runner plan plus a separate strength plan to reconcile after publication.

Two structures were considered. **Independent generation followed by calendar merge** is easy to compose, but each specialist can already consume the same availability, recovery capacity or lower-body window. A later adapter would then repair a preventable conflict. **Integrated candidate generation and joint feasibility checking** is selected: specialists offer bounded supported variants under one snapshot; the planner considers their complete combinations before proposal. This does not authorize iterative LLM negotiation, invented spacing or a universally optimal schedule. A bounded familiar week can remain the preferred structure when it meets the goal and current constraints; novelty has no preference.

Inputs are references to the one AthleteState and confirmed GoalPriorityModel, phase/event, known current capacity and recent exposure coverage, actual availability windows with timezone and duration, equipment/terrain, movement/calibration eligibility, double-session preference, restrictions/holds, authorized purposes, reviewed recipe/policy bundle, and any admissible athlete-response hypotheses. Missing age-of-training in running is not completed using strength experience. Missing sensor data is not zero capacity or low readiness.

Output is a **proposal**, including full executable session references and versions, weekly structure, placement, protected/flexible/optional roles, comparison trace, multidimensional demand, envelopes, dependencies and authority requirements. First adoption is `action_class=REPLAN`, `scope=INITIAL`, `effect=APPLY_PLAN_CHANGE`, `plan_base_ref=NONE`, `adequacy=NOT_APPLICABLE_INITIAL` under AEOS §10.2.5. It requires a current exact-scope act. Generation is not acceptance, execution, export or longitudinal-learning consent. A continuation for the next horizon is also REPLAN; it does not replace a valid current week automatically.

## HP-02 — Feasible initial week before adaptation

1. **Freeze the decision snapshot.** Bind subject, purpose/permission revisions, goals, availability, current facts frontier, all restriction/hold epochs, phase and current approval/revocation state. Check HC01–10 for the applicable context. Unknown eligibility routes to ASK; a clinical dependency routes to E/HOLD; missing recipe authority routes to D/HOLD.
2. **Resolve sporting coverage.** For each goal and modality select only a recipe whose population, skill, calibrated target method, equipment, phase, current exposure and evidence conditions match. Coverage of a family name does not instantiate its dose. Each session instantiation carries the exact prescription hash and SSCTR decision reference. A review-pending fixture is available for offline demonstration only.
3. **Create a finite candidate task set.** Supported recipe variants, durations and permitted goals come from the reviewed registry, not generated arbitrary doses. Each task declares essential stimulus, optional suffix, configuration, priority role, forecast demand dimensions and permissible location/time windows. Planned rest occupies no training session and implies no physiological clearance. Do not silently fill every free window.
4. **Apply hard scheduling constraints.** Each required task fits wholly in a real window with equipment access, travel/setup explicitly supplied when material, no overlap and no conflict with a locked or executing session. A double is allowed only on an explicitly permitted day and when both sessions and the joint interaction are covered. A reported available morning and evening does not mean the athlete wants doubles. Explicit no-doubles removes those candidate schedules.
5. **Apply supported interaction predicates.** Evaluate order, shared local demand, novelty, event proximity, session-specific recovery and subsequent key sessions over the affected horizon. A temporal gap is a schedule fact; `gap >= reviewed_rule.min_gap` is a physiological constraint only when that exact rule supports it. No universal 6/24/48-hour rule is supplied. Missing interaction authority is `INTERACTION_UNASSESSED`, not an infinite penalty, safe interval or numeric zero. Remove the dependent candidate or retain it only as a clearly non-executable research witness.
6. **Search complete schedules.** Enumerate finite recipe combinations, permitted task orderings and windows deterministically. For each, solve start/end inequalities using actual window endpoints and any supported relative-time constraints; earliest feasible boundaries give a reproducible realization for equivalent schedules. Do not round an athlete window into an arbitrary training grid or infer a physiological gap from search resolution. Stable IDs and canonical ordering break ties only after material equivalence has been established. An implementation may use a constraint solver, but its output must satisfy the same predicates and record every excluded material alternative.
7. **Compare whole-plan candidates.** Apply HC first, then the goal-specific partial comparator below, essential-stimulus preservation, supported evidence, expressed schedule preferences and least disruption. Existing familiar supported structure is preferred among otherwise equivalent candidates. A numerical combined load or hidden goal weight cannot turn an incomparable pair into a winner.
8. **Emit proposal or scoped control.** A supported feasible maximum may be recommended. A material trade-off unresolved by confirmed preferences yields ASK with the competing concrete plans and smallest deciding choice. Contradictory user constraints yield UNSAT diagnostics and ASK to change only a named constraint; no covert reduction of a coprimary goal. Absence of an approved sporting solution yields HOLD/review, not a question asking the athlete to supply scientific authority. Search-budget exhaustion is `SEARCH_INCOMPLETE`, distinct from proven UNSAT; return an independently valid already-evaluated option if one exists, otherwise hold the dependent proposal.
9. **Adoption and future use.** Show the full scoped revision and declared trade-offs, obtain valid adoption, recheck the commit guard and preserve its history. Export is a separate future effect. The next observation updates the model, then AE asks whether this adopted plan remains adequate. A schedule is never deliberately made deficient so the adaptation engine can demonstrate activity.

`UNSAT` means no candidate satisfies the finite *declared* recipe set and constraint set under a completed search. Include minimal conflicting subsets where computable; otherwise label the supplied conflict set as sufficient rather than minimal. Distinguish `NO_SUPPORTED_RECIPE`, `INPUT_UNKNOWN`, `PRIORITY_UNRESOLVED`, `SCHEDULE_UNSAT`, `INTERACTION_UNASSESSED` and `SEARCH_INCOMPLETE`. No claim of globally impossible training follows from a finite candidate set.

## HP-03 — Three genuine priority modes

| Mode | What is protected | What may flex | Material unresolved conflict |
|---|---|---|---|
| RUN_FIRST | Confirmed run outcome and supported key stimuli for that phase; strength remains a first-class specified secondary objective. | Supported strength dose/configuration/placement within its accepted development or maintenance intent; flexible run placement if essential run intent survives. | ASK if the secondary floor or event trade-off has not been accepted; do not erase strength as incidental conditioning. |
| STRENGTH_FIRST | Confirmed strength outcome, performance conditions and progression opportunities for that phase; running retains its own declared purpose. | Supported running dose/family/placement within its accepted intent and compatible strength schedule. | ASK before sacrificing a meaningful run objective or before unapproved ordering; being Strength-first does not prohibit every hard run. |
| BALANCED_HYBRID | Both explicit coprimary outcomes, each with a reviewed acceptable stimulus envelope and athlete-confirmed trade-off bounds. | Placement or variants preserving both; confirmed alternation of block emphasis may be a candidate. | Compare vectors by Pareto dominance. If one preserves running better and another strength better, they are INCOMPARABLE until an authorized trade-off resolves them. Never default to runner-first, 50/50 dose or a weighted sum. |

For Run-first a run-preserving option may outrank an otherwise equivalent strength-preserving option only after both are covered and its secondary trade-off is already authorized. Strength-first reverses that protection under the same facts. Priority alone neither proves that the current plan is inadequate nor authorizes larger dose. In Balanced, an event date is a fact to discuss; it does not silently grant running temporary priority.

**Balanced alternation candidates:** (a) simultaneous supported development in both within tolerance; (b) athlete-confirmed phase alternation with explicit current emphasis, protected coprimary maintenance/development floor, next review boundary and later phase intent. Option (b) is eligible only if the relevant recipes and multicycle trade-off are supported and accepted. Alternation is not a debt contract or permission to compensate later. If current windows cannot support both minimum intended stimuli, ASK to revise goals/windows/phase; do not call an underdosed mode Balanced. A later phase is re-evaluated using actual response and may be maintained, changed or held; calendar alone cannot earn progression.

## HP-04 — Session roles, demand and envelopes

`PROTECTED`, `FLEXIBLE`, `OPTIONAL` are planning roles, not safety classes. Protected means identified essential stimulus/intent cannot be removed or moved outside its approved bounds without a material proposal. Flexible means explicit admissible placement or prescription alternatives exist; it is not license to mutate silently. Optional means its omission was accepted *beforehand* without defeating the intended goal; adding it later is not automatically free or within tolerance. The same session has an immutable role revision and may have a protected core plus optional suffix.

Weekly distribution is a vector with separate units and coverage: run duration/distance by family and method, work/recovery density, long-session exposure and terrain/novelty; strength work sets by configuration/pattern and approved muscle attribution, reps/load convention/RIR/rest, novelty and local demand; temporal density, order, overlap and known uncertainty. Time may be totaled as logistics, but not as a cross-sport fatigue score. Shared-muscle attribution is many projections of the same exposure, not extra sessions. Predicted demand is an estimate from exercise/session metadata × actual prescription × athlete/context; actual exposure supersedes the matched planned segment once.

An envelope is a **finite, reviewed multidimensional admissible set**, bound to subject/context/recipe/policy/approval/plan/agency revisions. Every dimension declares unit, bounds or finite alternatives, essential-stimulus predicate, expiry trigger and permission. Coupling predicates constrain the complete combination: volume and intensity ranges are not a Cartesian product unless specifically reviewed; reducing recovery while adding work cannot hide in separate legal knobs. Planned movement windows identify exact allowed days/time intervals, equipment, dependent sessions and next-horizon impact. A single allowed component does not validate its composition with another.

Accepted envelopes can encode execution choices already shown and accepted, such as a predeclared compatible target-method fallback. Selecting a fully specified preaccepted branch may constitute execution of the chosen prescription. A newly computed change to the adopted plan remains a proposed mutation under AEC §§3/5 and needs current agency even if each number falls within an earlier range. Initial proposal, chosen plan, executing revision and observed work remain distinct.

## HP-05 — Concrete candidate witnesses and rejected shortcuts

These are structural pointers for the synthetic scenarios, not sporting approvals. A Run-first familiar-week candidate can place `RUN-E30`, `RUN-CRUISE3X6`, `RUN-LONG60`, `STR-LOWER-STRENGTH` and `STR-UPPER-STRENGTH` only when that athlete's actual capacity, windows, individual recipe conditions and full joint schedule are covered. Strength-first may select supported strength tasks first and then place eligible running support; it may reject the Run-first schedule because of a concrete loss to the accepted strength aim. Balanced must compare both complete outcome vectors and may select a different arrangement or ASK rather than copy either.

Reject: automatic five-day templates for all athletes; same time available interpreted as same recovery; hidden cumulative exercise fatigue scores; a generic easy run used to bridge unknown eligibility; universal spacing; event implies priority; missed work compressed into remaining days; optional work converted to mandatory on a positive wearable day; future candidate doses treated as licensed because the athlete accepts them. Recipe IDs resolve in `RUN_PRESCRIPTION_ENGINE.md` / `STRENGTH_PRESCRIPTION_ENGINE.md`; their presence here does not imply review status.

Consumers: `POL-07` double session; `POL-08` interference; `POL-13/14` taper/race week; `POL-19` outside-envelope mutation; the initial-week and multicycle end-to-end fixtures. `COACHING_CONTRACTS.json` specifies HP inputs, outputs, errors and invariants. `SCIENTIFIC_SYNTHESIS.md`, `LITERATURE_SNAPSHOT.json` and exact `SCIENTIFIC_DECISION_REGISTRY` records carry sporting support where reviewed. Pending claims and unsupported combinations remain non-executable gaps. This author supplies no independent Architecture Eval or SSCTR PASS; the exact revision must be judged separately.
